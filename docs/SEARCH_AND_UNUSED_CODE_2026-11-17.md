# 검색 점수와 미사용 기능 점검

기준: 2026-11-17. “미사용”은 GUI·콘솔의 일반 실행에서 호출하지 않는다는 뜻입니다.

## 현재 검색

1. 모드 선택 없이 본문·이미지를 모두 검색합니다. 내부 개별 검색은 원본 유사도를 반환합니다.
2. 모델별 하한(본문 0.4, 이미지 0.2) 미달은 제외합니다. 생성자의 `document_min_score`, `image_min_score`로 조정하며 -1 이상 1 미만의 유한한 값이어야 합니다. 실제 관련성을 보증하는 기준은 아닙니다.
3. 통합 정렬값은 `(원본 유사도 - 모델별 하한)/(1 - 모델별 하한)`입니다. 파일별 최고 값 하나를 사용하고 두 목록에 등장했다고 더하지 않습니다. 동점은 파일 경로 순서로 정렬합니다.
4. SHA-256이 같은 내용은 한 번만 반환하며 해시가 없으면 경로로 구분합니다. 필터·중복 제거 후 기본 최대 5개를 반환하고 부족한 자리를 낮은 점수로 채우지 않습니다.
5. `SearchResult`는 파일·원본 점수·선택 모델·정렬값·양쪽 원본 점수를 따로 담습니다. 기존 `파일, 점수 = result` 사용도 유지합니다. GUI·콘솔에는 선택 모델과 원본 유사도를 표시하며 정렬값을 유사도나 확률로 표시하지 않습니다.

본문과 이미지의 원본 점수를 보정 없이 직접 비교하거나 순위를 고정 점수로 치환하지 않습니다. 하한을 0, 유사도 1을 1에 대응시키는 선형 보정은 운영상의 초기 규칙일 뿐, 학습된 확률·통계적 모델 보정이 아닙니다. 모델이 관련 없는 내용을 높게 평가하면 여전히 상위에 남을 수 있습니다.

## 실제 모델 비교와 선택 이유

test.sample 38개 지원 파일(본문 544개·이미지 573개 청크)에서 실제 모델로 15개 검색어를 비교했습니다. 같은 자료를 기준 설정과 평가에 사용한 탐색 실험이며 독립 검증 세트가 아닙니다.

| 검색어 | 본문 최고 원본 점수 | 이미지 최고 원본 점수 | 현재 결과 |
|---|---:|---:|---|
| 누워있는 고양이 | 0.129630 | 0.260748 | Test2·Test3·Test1 세 장. 데이터베이스 PDF 제외 |
| 피자 | 0.292157 | 0.232131 | 피자 사진 한 장 |
| 판다 | 0.303794 | 0.258404 | 판다 사진 한 장 |
| 관계형 데이터베이스의 기본키와 외래키 | 0.730370 | 0.320011 | 데이터베이스 문서 유지 |
| 동적 계획법의 최적 부분 구조와 중복 부분 문제 | 0.807783 | 0.303930 | 동적계획법 PDF 1위 |

누워있는 고양이는 필터 후 RRF로도 동일한 세 사진 순서였습니다. 이 사례의 개선은 주로 필터에서 왔으며 새 정렬식의 일반적인 우위를 입증하지 않습니다. RRF는 서로 다른 모델 점수를 직접 비교하지 않는 장점이 있지만 통과한 결과의 유사도 격차를 버리고 중복 등장에 가산합니다. 원본 점수 보존 요구에 맞춰 현재는 기준 초과 비율을 사용했습니다.

제외 기준으로 사용한 사진 검색어의 본문 최고값 범위는 약 0.13~0.35였습니다. 0.4/0.2는 해당 자료의 초기 조정값이며 다른 검색어·문서에서 정답을 누락하거나 무관 결과를 남길 수 있습니다. 정확도·신뢰도 퍼센트로 해석하지 않습니다.

실패 사례도 남습니다. 로지스틱 회귀 PDF는 본문이 추출되지 않는 이미지 문서여서 다른 기술 문서의 높은 본문 점수가 앞섭니다. 타입스크립트 검색에도 의심 결과가 남습니다. 강아지 검색에서는 딥러닝 PDF 내부 이미지가 일반 사진보다 높아 모든 문서 결과를 오답으로 판정하지 않았습니다. OCR/추출 확인·실제 정답 세트·후속 재정렬 평가가 필요합니다.

동일 내용 파일 묶음 6개도 확인했고 현재는 해시로 중복을 제거합니다. 대표 파일명은 정렬 결과에 따라 달라질 수 있습니다. 전체 원시 점수·필터 후 RRF 비교·현재 실제 재검색 기록은 로컬 `study/raw_similarity_check_2026-11-17`에 보관합니다. GUI 육안 검증은 하지 않았습니다.

## encode_with_crops()

전체와 네 사분면을 encode_batch로 처리합니다. 일반 입력은 `(5, 512)` float32, 가로나 세로가 2 미만이면 전체 하나의 `(1, 512)`를 반환합니다. 모델 대역으로 실제 분할·배치 처리·반환 형태·FAISS 연결을 검증했습니다. 실제 모델의 crops 속도·품질은 검증하지 않았고 기본 분석에는 연결하지 않았습니다.

현재 분석은 파일 내 이미지를 encode_batch로 묶어 벡터 행과 청크를 같은 개수로 연결합니다. crops로 각 원본을 5개로 늘리려면 벡터 행과 원본 청크 메타데이터를 함께 펼쳐야 하며 함수 이름만 바꿔서는 맞지 않습니다. 각 행을 벡터 목록에 펼치고 행마다 원본 경로의 청크 메타데이터를 등록해야 합니다. 사분면이 물체·자세를 자를 수 있고 보통 벡터 수가 5배로 늘어 품질·시간을 비교한 뒤 연결해야 합니다.

## 미연결·보조 기능

| 코드 | 일반 실행에서의 상태 |
|---|---|
| ImageEncoder.encode_with_crops | 미연결. 기본 활성화하지 않음. |
| ImageEncoder.encode_batch | 현재 일반 분석에 사용. 더 이상 미연결 기능이 아님. |
| ImageEncoder.encode | 단일 이미지 API. 최적화 후 일반 분석은 encode_batch를 사용하며 이 함수는 보조·실험용으로 유지함. |
| DocumentEncoder.encode_batch | 현재 문서 내부 이미지 분석에 사용. 단일 encode는 보조 API로 유지함. |
| DocumentEmbedder.search | 자체 코사인 검색 대안. 앱은 FAISS를 사용하며 별도 테스트만 호출함. |
| FaissManager.save/load | 앱의 영구 저장·재시작 복원과 미연결. 이번 실제 비교 도구에서는 동일 인덱스 복원에 사용함. |
| DocumentEmbedder.chunks | 자체 search·검증용으로 보관. 실제 앱 순위 비교는 FAISS. |
| documents/images 검색 분기 | 통합 검색·진단에서 실제 사용함. 미사용 코드가 아님. |
| 인코더 기본 모델 생성 분기 | 단독 사용용. 앱에서는 이미지·검색어 모델을 공유함. |
| tests/image_model_comparison.py | 수동 실험 도구. unittest 자동 발견 대상이 아니며 자료 경로 확인 필요. |

file_hash는 이제 통합 결과의 내용 중복 제거에 사용합니다. 팀원 제공 API는 삭제하지 않았습니다. 전체 58개 테스트가 통과했으며 실제 모델 비교와 테스트 대역 검증을 구분했습니다.

## 분석 속도 검토

동일 CPU·FP32·4스레드·같은 프로세스에서 test.sample 38개를 기존 경로와 최적화 경로로 한 번씩 분석했습니다. 모델 로딩 약 7.0초는 제외했습니다.

| 단계 | 기존 | 최적화 |
|---|---:|---:|
| 파일 읽기 | 19.9초 | 21.2초 |
| 이미지 처리 | 38.9초 | 28.9초 |
| 본문 인코딩 | 42.1초 | 37.4초 |
| 분석 전체 | 101.5초 | 88.0초 |

이미지는 파일 내 그림을 기존 encode_batch로 묶어 모델 호출을 573회에서 90회로 줄였습니다. 그림 573개와 파일·페이지 메타데이터는 유지합니다. 동일 본문은 한 번만 인코딩해 모델 입력을 544개에서 447개로 줄이되 원래 본문 청크 544개를 FAISS에 연결합니다. 잘못된 배치 개수는 인덱싱 전에 오류로 알립니다.

이 실행에서는 전체 분석이 약 13.2% 줄었습니다. 기존 경로를 먼저 실행한 단일 비교라 캐시·실행 순서 영향을 배제하지 못하며 실제 GUI 체감 시간의 보장은 아닙니다. 전체 벡터 최대 차이는 본문 1e-07, 이미지 5.1e-07였고, 누워있는 고양이의 세 사진 순서와 원본 점수가 유지됐습니다.

기본 CPU 스레드는 12개였고 작은 표본에서는 이를 4개로 줄여도 빨라지지 않아 앱의 스레드 설정은 바꾸지 않았습니다. 모델을 다시 만드는 비용과 파일 읽기·본문 처리 비용은 남습니다. 영구 분석 캐시·앱 저장/복원은 아직 연결하지 않았습니다. 원시 측정은 로컬 study/analysis_performance_2026-11-17에 있습니다.
