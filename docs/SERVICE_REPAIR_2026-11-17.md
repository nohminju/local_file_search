# 2026-11-17 서비스 오류와 수정 사항

## 오류 원인

`bc66a2d`에서 `connection/service.py`의 `DocumentSearch` 클래스가 삭제되고 클래스 밖의 `search_hybrid(self, ...)`만 남았습니다. 그 결과 `app.py`와 기존 테스트가 클래스를 가져오지 못하는 ImportError가 발생했습니다. 분석·저장 흐름과 새 함수가 호출하는 기존 `search()`도 함께 없어졌습니다.

비유하면 두 순위표를 합치는 기능을 넣으면서, 순위표를 만드는 작업실까지 지운 상태였습니다.

## 수정 내용

- 정상 버전 `c829815`에서 클래스·생성자·분석·개별 검색을 복원했습니다. 최신 DB·FAISS·테스트 자료는 유지했습니다.
- 통합 검색을 클래스 내부에 넣고 `search(query)`에서 기본으로 호출하도록 연결했습니다. 후속 수정으로 모델별 하한을 통과한 원본 유사도를 보존하고 기준 초과 비율로 정렬합니다. 같은 파일은 ID로 묶고 같은 내용은 해시로 중복 제거하며, 중복 등장 보너스는 주지 않습니다. [후속 순위 수정](SEARCH_AND_UNUSED_CODE_2026-11-17.md)
- 결과 통합 반복문을 정리하고 음수 `k`를 거부했습니다. 한쪽 검색 대상이 없으면 다른 쪽 결과를 사용합니다.
- GUI·콘솔의 모드 선택을 없애고 검색할 때 본문·이미지를 자동으로 함께 검색하도록 했습니다. 결과는 원본 유사도와 해당 모델로 표시합니다.
- 통합 검색 회귀 테스트 5개를 추가하고 GUI 작업·상태 전환 검증을 보완하고 콘솔에 모드 질문이 없는지 검증을 추가했습니다.

## 검증

AI가 전체 58개 테스트 통과를 확인했습니다. 실제 로더·SQLite·FAISS와 모델 출력 대역으로 기존 분석·검색, 유사도 필터·통합·중복 제거·결과 수 제한, 본문/이미지 전용 폴더, 빈 입력·잘못된 하한 설정, GUI 작업 처리를 검증했습니다. 실제 모델로 한 폴더·15개 검색어도 비교했으며 일반 품질을 보장하는 독립 평가가 아닙니다. GUI 육안 검증은 실행하지 않았습니다.

수정 전에는 한글 임시 경로로 인한 FAISS 저장 오류도 발생했습니다. 검증에는 영문 임시 경로를 사용했으며, 제품의 경로 처리를 수정한 것은 아닙니다. 손상 PDF 테스트의 진단 메시지는 의도한 실패 입력에서 출력됐습니다.
