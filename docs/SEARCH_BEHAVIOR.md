통합 기준 확인: 2026-11-25. 최신 main·통합본 실제 32질의 비교와 원본 점수는 [별도 비교 보고서](MAIN_COMPARISON_2026-11-25.md)에 있습니다. 아래 2026-11-20 표는 당시 평가로 보존합니다.

main `fc2a48d`의 DeepL 양방향 번역을 연결했습니다. app.py는 이미지용 한→영, 본문용 영→한 함수를 서비스에 주입합니다. 한국어 본문 입력은 그대로이며, 본문 어댑터는 부모 OpenCLIP의 한→영 번역을 상속하지 않습니다. 번역 실패·빈 결과·잘못된 반환은 원문으로 대체합니다. `.env` 또는 환경 변수의 DEEPL_API_KEY가 필요합니다. 단위 테스트는 API를 호출하지 않으며, 이후 별도 실제 비교에서 DeepL 요청 41건 성공을 확인했습니다. 기존 Google 요청 제한과 별도 영어 입력 비교는 과거 이력입니다.

GUI는 main의 일치도 표시를 유지합니다. 원본 0.15~0.32를 0~100%로 환산한 뒤 범위를 제한하는 표시값으로, 정확도·확률이 아닙니다. 정렬에는 원본 점수만 사용합니다.

2026-11-20의 유사도 정책 변경과 본문 검색에 관한 혼동·원인·팀원별 이력은 [통합 문제·연구일지 초안](INTEGRATION_NOTES_2026-11-20.md)에 별도로 정리했습니다.

## 현재 실행 흐름 — 분석부터 결과까지

1. GUI에서 폴더를 선택하고 분석을 누르면 app.build_service가 본문용 ko-sroberta, 이미지용 OpenCLIP, 임시 DB와 별도 FAISS 인덱스를 조립합니다.
2. 서비스는 하위 폴더까지 지원 파일을 수집하고 본문·이미지를 읽습니다. 긴 본문은 분할하고 동일 본문은 중복 인코딩을 줄이되 파일·페이지 연결은 보존합니다.
3. 본문은 768차원, 이미지는 512차원 벡터로 인덱싱하고 파일 정보는 SQLite와 연결합니다.
4. 본문 검색은 영→한 번역 후 ko-sroberta, 이미지 검색은 한→영 번역 후 OpenCLIP으로 검색어를 인코딩합니다. 번역 실패 시 원문을 사용합니다. 본문 어댑터는 검색어를 추가 번역하지 않습니다.
5. 각 인덱스에서 코사인 유사도를 구하고 같은 파일의 청크를 파일별 최고 점수로 묶습니다.
6. 통합검색은 일반 이미지의 이미지 점수, PDF/PPTX의 본문·내부 이미지 중 높은 원본 점수를 선택해 정렬합니다. 내용 해시 중복을 묶고 동점은 경로 순이며 기본 5개를 표시합니다.
7. GUI는 선택 근거와 원본 유사도, 팀원이 추가한 환산 일치도 %를 표시합니다. (점수-0.15)/(0.32-0.15)×100을 0~100으로 제한하므로 원본 0.32 이상은 모두 100%입니다. 정확도·확률이 아니며 정렬에는 사용하지 않습니다.

앱 검색에는 RRF·하한·점수 합산·재정렬 모델을 연결하지 않았습니다. 재실행 시 재분석합니다. 다른 PC의 설치와 GUI 실행·오류 확인은 [프로젝트 README의 4번 절](../README.md#4-gui-설치와-실행), 이번 팀원 변경과 로컬 통합 수정의 구분은 [담당 범위](CODE_OWNERSHIP.md)를 참고하세요.

## 최종 선택과 동작

사용자는 파일명 검색을 사용하지 않기로 했고, 무거운 재정렬 모델 다운로드를 삭제하도록 요청했습니다. 이어 일반 이미지는 이미지 유사도만, PDF/PPTX는 본문·내부 이미지 유사도 중 높은 값으로 통합 정렬하도록 지정했습니다. 이 문서가 현재 구현 기준이며 이전 파일명·하한·재정렬 실험 설명은 이력입니다.

| 파일 종류 | 최종 점수 |
|---|---|
| JPG/JPEG/PNG/WEBP | 이미지 검색의 최고 원본 코사인 유사도 |
| PDF/PPTX | 본문 최고 유사도와 내부 이미지 최고 유사도 중 큰 값 |
| 한 종류의 내용만 추출된 PDF/PPTX | 존재하는 쪽의 원본 유사도 |

선택한 원본 유사도의 내림차순으로 정렬합니다. 점수를 더하지 않고 기준 초과 비율로 보정하지도 않습니다. 앱 검색 흐름은 하한·RRF·재정렬 모델을 사용하지 않습니다. 0 또는 음수의 유한한 점수도 반환하며 NaN/무한대만 유효하지 않은 값으로 제외합니다. 같은 내용의 파일은 SHA-256으로 묶고 동점은 경로로 정합니다.

ko-sroberta 본문 점수와 OpenCLIP 이미지 점수는 같은 신뢰도로 학습·보정된 값이 아닙니다. 따라서 이 직접 비교 규칙이 항상 최적의 관련성 순서라는 보장은 없습니다. 이번에는 사용자가 지정한 단순한 원본 점수 규칙을 그대로 구현했습니다.

최신 FAISS의 개별 검색에서는 min_score 인자가 제거됐습니다. 게시 직전 보존 병합한 팀원 0bf2242에서 미사용 search_combined()는 제거됐으며, DocumentEmbedder.search()는 앱에서 호출하지 않습니다. 벡터의 L2 정규화는 코사인 계산을 위해 유지합니다.

## 파일명과 모델 정리

- 파일명·경로는 결과 표시, 파일 열기, 원본 위치·DB ID 연결에만 사용합니다. 모델 입력 텍스트에 붙이지 않습니다.
- 파일명 청크 생성 코드를 제거하고, 이전 인덱스의 filename 청크도 본문 검색에서 제외합니다. 실제 재분석 인덱스에 filename 청크가 0개임을 검증했습니다.
- Qwen3-VL-Reranker-2B 다운로드 폴더에서 4,271,035,525바이트(약 4.27GB)를 삭제하고 경로가 없어졌음을 확인했습니다. 기존 ko-sroberta·OpenCLIP 캐시는 유지했습니다.
- 새 재정렬 모델의 앱 연결·준비 스크립트·실험 테스트 코드를 정리했습니다. 앱이 Qwen을 다시 다운로드하거나 로드하는 경로는 없습니다.
- 파일명 포함 재정렬 비교는 사용자 결정 변경으로 중단했습니다. 그 일부 결과를 최종 구현의 검증 결과로 사용하지 않았습니다.

## 본문과 이미지가 실제로 들어오는 경로

PDF의 텍스트 계층과 PPTX의 글상자·표는 OCR 없이 읽습니다. 실제 확인에서 동적계획법.pdf는 본문 34청크·10,736자, 페르소나_경로맵.pptx는 본문 3청크·1,997자였습니다. 로지스틱회귀.pdf는 본문 0개·이미지 23개이므로 그림 속 글을 본문으로 검색할 수 없습니다. 파일명 검색도 현재 제거했습니다.

추출 본문은 별도 TXT 파일로 저장하지 않고 chunk.text로 전달합니다. ko-sroberta 입력 길이 128에서 특수 토큰 2개를 제외한 126토큰 단위·32토큰 겹침으로 나눕니다. 실제 사진과 문서 내부 그림은 하나의 공통 ImageEncoder(OpenCLIP)를 쓰고 원본 DocumentEncoder의 공유 인코더 인자를 사용합니다. 본문은 별도 SentenceDocumentEmbedder(ko-sroberta)를 사용합니다.

## 2026-11-20 구조 정리 기록

- 앱에서 사용하지 않는 OpenCLIP/ko-sroberta 본문 전환 분기를 제거했습니다. 현재 본문 모델은 ko-sroberta 하나입니다. 과거 모델 비교 기록과 원래 인코더 API는 보존합니다.
- score와 항상 같았던 sort_score 저장 필드를 제거했습니다. 정렬·표시는 score 하나를 사용하고 본문/이미지 원본 점수는 비교에 필요하므로 유지합니다.
- 지원 확장자는 원본 DocumentScanner.SUPPORTED_EXTENSIONS를 사용합니다. 이미지·문서 검색 경로 분류는 connection/service.py에서 처리하며 팀원 로더는 수정하지 않습니다.
- 긴 본문 분할은 실제 128토큰 잘림을 막기 위해, 모델 공유는 중복 로딩을 막기 위해, GUI 작업 큐는 분석 중 화면 응답을 위해 유지했습니다. DocumentEncoder는 팀 모듈 연결 규격의 얇은 래퍼로 유지했습니다.
- 무거운 재정렬 모델과 파일명 검색의 실행 코드는 현재 경로에 없습니다. 새 설정 계층·플러그인 구조·범용 팩토리 같은 추상화는 추가하지 않았습니다.

원본 점수 계산과 정렬 규칙은 이 구조 정리 전 실제 16개 질의에서 검증한 것과 동일합니다. 팀원 파일 복원 후 회귀 테스트 79개가 통과했습니다. 전체 실모델 분석은 구조 정리 후 다시 실행하지 않았습니다.
