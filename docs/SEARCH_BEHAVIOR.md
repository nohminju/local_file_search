# 현재 검색 동작과 검증

최종 확인: 2026-11-20.

오늘 유사도 정책 변경과 본문 검색에 관한 혼동·원인·팀원별 이력은 [통합 문제·연구일지 초안](INTEGRATION_NOTES_2026-11-20.md)에 별도로 정리했습니다.

## 최종 선택과 동작

사용자는 파일명 검색을 사용하지 않기로 했고, 무거운 재정렬 모델 다운로드를 삭제하도록 요청했습니다. 이어 일반 이미지는 이미지 유사도만, PDF/PPTX는 본문·내부 이미지 유사도 중 높은 값으로 통합 정렬하도록 지정했습니다. 이 문서가 현재 구현 기준이며 이전 파일명·하한·재정렬 실험 설명은 이력입니다.

| 파일 종류 | 최종 점수 |
|---|---|
| JPG/JPEG/PNG/WEBP | 이미지 검색의 최고 원본 코사인 유사도 |
| PDF/PPTX | 본문 최고 유사도와 내부 이미지 최고 유사도 중 큰 값 |
| 한 종류의 내용만 추출된 PDF/PPTX | 존재하는 쪽의 원본 유사도 |

선택한 원본 유사도의 내림차순으로 정렬합니다. 점수를 더하지 않고 기준 초과 비율로 보정하지도 않습니다. 앱 검색 흐름은 하한·RRF·재정렬 모델을 사용하지 않습니다. 0 또는 음수의 유한한 점수도 반환하며 NaN/무한대만 유효하지 않은 값으로 제외합니다. 같은 내용의 파일은 SHA-256으로 묶고 동점은 경로로 정합니다.

ko-sroberta 본문 점수와 OpenCLIP 이미지 점수는 같은 신뢰도로 학습·보정된 값이 아닙니다. 따라서 이 직접 비교 규칙이 항상 최적의 관련성 순서라는 보장은 없습니다. 이번에는 사용자가 지정한 단순한 원본 점수 규칙을 그대로 구현했습니다.

FAISS에 남아 있는 선택적 min_score 기능은 현재 서비스에서 지정하지 않습니다. DocumentEmbedder.search()도 앱에서 호출하지 않으므로 해당 보조 함수의 하한·RRF 관련 설명을 현재 통합 정책으로 해석하지 않습니다. 벡터의 L2 정규화는 코사인 계산을 위해 유지합니다.

## 파일명과 모델 정리

- 파일명·경로는 결과 표시, 파일 열기, 원본 위치·DB ID 연결에만 사용합니다. 모델 입력 텍스트에 붙이지 않습니다.
- 파일명 청크 생성 코드를 제거하고, 이전 인덱스의 filename 청크도 본문 검색에서 제외합니다. 실제 재분석 인덱스에 filename 청크가 0개임을 검증했습니다.
- Qwen3-VL-Reranker-2B 다운로드 폴더에서 4,271,035,525바이트(약 4.27GB)를 삭제하고 경로가 없어졌음을 확인했습니다. 기존 ko-sroberta·OpenCLIP 캐시는 유지했습니다.
- 새 재정렬 모델의 앱 연결·준비 스크립트·실험 테스트 코드를 정리했습니다. 앱이 Qwen을 다시 다운로드하거나 로드하는 경로는 없습니다.
- 파일명 포함 재정렬 비교는 사용자 결정 변경으로 중단했습니다. 그 일부 결과를 최종 구현의 검증 결과로 사용하지 않았습니다.

## 본문과 이미지가 실제로 들어오는 경로

PDF의 텍스트 계층과 PPTX의 글상자·표는 OCR 없이 읽습니다. 실제 확인에서 동적계획법.pdf는 본문 34청크·10,736자, 페르소나_경로맵.pptx는 본문 3청크·1,997자였습니다. 로지스틱회귀.pdf는 본문 0개·이미지 23개이므로 그림 속 글을 본문으로 검색할 수 없습니다. 파일명 검색도 현재 제거했습니다.

추출 본문은 별도 TXT 파일로 저장하지 않고 chunk.text로 전달합니다. ko-sroberta 입력 길이 128에서 특수 토큰 2개를 제외한 126토큰 단위·32토큰 겹침으로 나눕니다. 실제 사진과 문서 내부 그림은 하나의 공통 ImageEncoder(OpenCLIP)를 쓰고 DocumentEncoder는 호환 래퍼입니다. 본문은 별도 SentenceDocumentEmbedder(ko-sroberta)를 사용합니다.

## GUI와 검증

- 통합검색: 파일 종류별 최고 원본 유사도순. 결과 카드에 선택된 본문 또는 이미지 점수를 표시합니다.
- 이미지 검색: 이미지 원본 점수순. 본문 검색: 추출한 글의 원본 점수순. 두 모드 모두 파일명 검색·하한을 사용하지 않습니다. 이미지 모드는 일반 사진과 문서 내부 그림을 함께 검색하며, 본문 모드에서는 추출 글이 있는 문서만 검색합니다.
- 실행 중인 GUI는 닫고 다시 실행한 뒤 폴더를 재분석해야 새 코드와 파일명 없는 인덱스가 적용됩니다.
- 구조 정리 후 회귀 테스트 80개 통과(11.268초). 이미지에 본문 점수 섞임 금지, 문서의 최고 점수 선택, 합산·보정·하한 없음, 음수 처리, 중복 제거, 파일명 미입력을 검증했습니다.
- 실제 16개 질의의 모든 결과에서 이미지 파일은 이미지 점수만 쓰고, 문서는 존재하는 본문·이미지 점수의 최댓값을 쓰는지 자동 확인했습니다.
- 새 GUI의 전체 실모델 흐름을 이번 단계에서 별도로 육안 재실행하지는 않았습니다. 기존 세 모드 배치는 유지했고 점수 라벨·호출 경로는 테스트했습니다.

## 실행

```powershell
python app.py --gui
python -B -m unittest discover -s tests -v
python -B tests/compare_similarity_search.py
```

추가 재정렬 모델은 필요 없습니다. 기존 모델의 최초 준비·파일 분석 시간은 남습니다. 지원 확장자는 DocumentScanner의 PDF/PPTX/JPG/JPEG/PNG/WEBP이고, OCR·PPT·HWP·TXT/MD/DOCX 지원은 이번 변경에서 추가하지 않았습니다. 샘플은 test_esset에 유지하며 study/의 Git 제외 설정을 유지했습니다. test_esset은 Git 제외 대상이 아닙니다.


## 구조·과설계 점검

- 앱에서 사용하지 않는 OpenCLIP/ko-sroberta 본문 전환 분기를 제거했습니다. 현재 본문 모델은 ko-sroberta 하나입니다. 과거 모델 비교 기록과 원래 인코더 API는 보존합니다.
- score와 항상 같았던 sort_score 저장 필드를 제거했습니다. 정렬·표시는 score 하나를 사용하고 본문/이미지 원본 점수는 비교에 필요하므로 유지합니다.
- 이미지·문서 확장자는 DocumentScanner의 두 상수와 그 합집합을 기준으로 로더·서비스가 함께 사용합니다.
- 긴 본문 분할은 실제 128토큰 잘림을 막기 위해, 모델 공유는 중복 로딩을 막기 위해, GUI 작업 큐는 분석 중 화면 응답을 위해 유지했습니다. DocumentEncoder는 팀 모듈 연결 규격의 얇은 래퍼로 유지했습니다.
- 무거운 재정렬 모델과 파일명 검색의 실행 코드는 현재 경로에 없습니다. 새 설정 계층·플러그인 구조·범용 팩토리 같은 추상화는 추가하지 않았습니다.

원본 점수 계산과 정렬 규칙은 이 구조 정리 전 실제 16개 질의에서 검증한 것과 동일합니다. 구조 정리 후 회귀 테스트 80개가 통과했습니다. 전체 실모델 분석은 구조 정리 후 다시 실행하지 않았습니다.

과거 설명과 원시 JSON은 로컬 전용 `archive/`, `records/`에 보관하고 Git에서는 제외합니다. 전후 비교 스크립트는 로컬 기준 JSON이 필요하며, 새 환경의 독립 샘플 검사는 `python -B tests/real_sample_search_check.py`로 실행할 수 있습니다.
