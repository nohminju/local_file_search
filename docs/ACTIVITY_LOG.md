이 기록에 해당하는 연결 코드 수정과 문서 정리는 아직 커밋하지 않은 상태에서 작성했다. 앞서 `service-merge`에서 만든 `f956c3b` 커밋과는 별개다.

### 내가 확인하고 판단한 부분

- 팀원 코드까지 모두 바꾸기보다는 내 담당 코드만 수정하고, 팀원 코드의 문제는 전달 문서로 정리하도록 범위를 정했다.
- FAISS가 연결된 뒤에는 기존 임시 이미지 비교 코드를 없애도 된다고 판단해 삭제를 요청했다.
- ‘파일별 중복 제거 후 상위 5개 반환’이 어디서 처리되는지 설명을 요청했다. `DocumentSearch.search()`에서 처리하며, 5개는 기본값이고 `top_k`로 바꿀 수 있다는 설명을 받았다.
- 불필요하게 구조를 늘리지 않고, 중복 코드와 주석을 정리하도록 요청했다.
- FAISS의 이전 인덱스 파일이 남는 문제가 현재 실행에도 영향을 주는지 여러 차례 질문했다. 현재 앱은 save/load를 호출하지 않는다는 설명을 확인한 뒤, 이 문제는 현재 수정 요청에서 빼고 ‘기능 업데이트 시 주의’로 분리하기로 했다.

CUDA 미사용, CPU FP32, 4스레드, 이미지·문장 배치 1, 모델별 학습 기준 전처리·토크나이저, 동일 한국어 원문, 정규화 벡터와 FAISS IndexFlatIP을 사용했다. 모델별 이미지 1회·문장 1회 워밍업 후 이미지 전체 3회, 검색어 20개를 순서를 섞어 3회 측정했다. 이미지 시간 표는 7장 전체 처리 3회의 중앙값이고, 문장 시간은 인코딩·FAISS 검색을 합친 60개 표본의 중앙값/P95다. 이미지 파일은 미리 읽었다. 다운로드·모델 준비·워밍업·파일 읽기·DB·GUI 시간은 제외했다.

| 모델 | 정답 1위 | MRR | Recall@3 | 이미지 7장 인코딩 | 검색어 처리 중앙값 | 검색어 처리 P95 |
|---|---|---|---|---|---|---|
| 기존 OpenCLIP | 18/18 | 1.000 | 100.0% | 0.490초 | 65.2ms | 139.9ms |
| SigLIP 2 Base | 18/18 | 1.000 | 100.0% | 2.240초 | 115.6ms | 227.9ms |

MRR은 첫 정답 순위의 역수 평균이고 Recall@3은 정답 이미지 중 상위 3개에 들어온 비율이다. 정답 없는 2개 검색어는 위 품질 지표에서 제외했지만 시간 측정과 전체 순위 기록에는 포함했다. 관련 없는 결과를 거절하는 기능은 평가하지 않았다. 모델 간 원시 점수 크기도 비교하지 않았다.

### 해석과 남은 일

이 7장에서는 두 모델 모두 정답을 찾았으므로 SigLIP 2의 품질 향상을 확인하지 못했다. SigLIP 2의 이미지 처리 시간은 기존의 약 4.57배, 검색어 처리 중앙값은 약 1.77배였다. 이번 CPU 조건에서는 기존 모델을 유지할 근거가 된다. 데이터가 작고 같은 대상의 바꿔 쓴 질문이 많아 일반적인 모델 우열이나 전체 서비스 속도로 확대 해석하지 않는다.

실제 모델을 실행한 비교이며 출력 대역을 사용하지 않았다. 앱·팀원 소스는 변경하지 않았다. 기존 32개 연결 테스트는 이미 통과한 상태로, 앱 코드가 그대로라 이번에 반복 실행하지 않았다. 사용자 정답 검수와 더 다양한 실제 이미지·문서로 평가 범위를 넓히는 일은 남아 있다. SigLIP 2는 768차원, 기존 모델은 512차원이라 앱에 교체 적용하려면 인코더와 인덱스를 함께 검토해야 한다. 사용자 요청에 따라 이 기록과 비교 실험 코드·결과·모델 설명을 함께 커밋하도록 준비했다. 커밋 결과는 Git 이력으로 확인한다.
