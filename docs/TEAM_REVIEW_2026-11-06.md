# 2026-11-06 연결 수정 및 팀원 전달 사항

기준 원본: `document-serch-demo-v1` 브랜치 `1d368f5`.
팀원 로더·인코더·SQLite·FAISS 원본은 수정하지 않았다. 아래 항목은 담당자에게 전달할 검토 내용이다.

## 내 담당 코드에서 반영한 내용

- `app.py`: 팀원 FaissManager를 만들어 DocumentSearch에 전달한다.
- `connection/service.py`: 본문·이미지 벡터와 청크를 각각 FAISS에 넣고, 같은 인코더로 검색어를 인코딩해 검색한다. 결과 dict의 경로를 SQLite 파일 ID로 연결한다.
- 같은 파일의 여러 청크는 최고 점수 하나만 남긴 뒤 상위 5개 파일로 제한한다. 본문·이미지 점수는 합치지 않는다.
- 기존 임시 이미지 비교 함수와 전용 테스트는 제거했다. 이미지 인코딩 분기의 중복과 설명을 반복하는 주석을 정리했다. GUI 작업 큐 구조는 유지한다.
- 테스트의 DB import·중복 갱신 기대값·GUI 작업 큐 처리를 현재 코드에 맞췄다. requirements에 faiss-cpu를 추가하고 MD를 갱신했다.
- 저장·복원, 통합 검색, 새 GUI 기능은 추가하지 않았다.

## 팀원에게 전달할 수정 요청

### 1. 로더: PPTX 슬라이드에 그림이 여러 개면 마지막 하나만 남음

- 위치: `file_loader/document_loader.py`의 `load_pptx()`.
- 재현 확인: 그림 2개가 들어 있는 슬라이드 1개를 만들면 이미지 청크가 1개만 나온다.
- 원인: 그림마다 `extracted_image`를 덮어쓰고, 슬라이드 끝에서 청크를 한 번만 만든다.
- 요청: 그림마다 별도 청크를 반환해 모든 그림이 검색되게 해 주세요. 텍스트 청크는 중복 생성되지 않도록 유지해 주세요.

### 2. DB: SQLite 연결이 명시적으로 닫히지 않음

- 위치: `database/manager.py`의 `_init_db()`, `save()`, `find_by_id()`.
- 재현 확인: 저장·조회 후 임시 폴더를 정리할 때 Windows에서 DB 파일 사용 중 오류가 발생했다. Python 3.14 테스트에서도 unclosed database ResourceWarning이 발생한다.
- 원인: `with sqlite3.connect(...)`는 commit/rollback을 처리하지만 연결 자체는 닫지 않는다.
- 요청: `contextlib.closing`과 트랜잭션 context를 함께 사용하거나 `finally: conn.close()`로 함수 종료 시 닫아 주세요. 테스트의 gc.collect()는 임시 파일 정리 보조일 뿐 해결책이 아니다.
- 참고: 동일 경로를 갱신하고 같은 ID를 반환하는 현재 upsert 동작은 정상 확인했다. created_at 유지 테스트도 통과했다.

### 3. 로더: PDF 이미지 열거 오류가 추출한 본문까지 버릴 수 있음

- 위치: `file_loader/document_loader.py`의 `load_pdf()`, `for image_file in page.images`.
- 코드 검토 사항: 이미지 목록 접근·반복 자체에서 오류가 나면 바깥 except로 이동해 빈 목록을 반환한다. 앞에서 정상 추출한 본문 청크도 버려진다.
- 요청: 페이지의 이미지 열거 오류를 별도로 처리해, 이미 추출한 본문과 다른 페이지 처리는 유지해 주세요.
- 이 항목은 예외 처리 범위를 확인한 사항이며, 실제 문제 PDF로 재현한 것은 아니다.

## 기능 업데이트 시 주의

현재 앱은 FAISS save/load를 호출하지 않아 아래 저장 문제는 현재 검색에 영향을 주지 않는다. 저장·복원 기능을 연결할 때 함께 수정하고 검증한다.

### FAISS 저장·복원 연결 시 이전 인덱스 정리

- 위치: `database/faiss.py`의 `save()` / `load()`.
- 재현 확인: 이미지 인덱스를 저장 → 새 매니저에서 본문만 추가해 같은 폴더에 저장 → 다시 load → 이미지 검색 시 IndexError.
- 확인 값: 이미지 인덱스 벡터 수 1, 이미지 메타데이터 수 0.
- 원인: 새 매니저의 img 인덱스가 None이면 예전 images.faiss 파일을 지우지 않지만 metadata.json은 빈 이미지 목록으로 덮어쓴다. 본문 인덱스도 같은 문제가 가능하다.
- 기능 연결 시 조치: 저장 시 더 이상 없는 인덱스 파일을 정리하고, load 시 인덱스 벡터 수와 메타데이터 수의 일치를 확인한다.
- 추가 코드 검토: add_documents/add_images도 벡터 수와 청크 수가 다르면 검색 중 메타데이터 인덱스 오류가 날 수 있으므로 추가 전에 길이를 검증해 주세요. 현재 연결 코드는 같은 순서·개수로 전달한다.

## 검증 범위

- Windows / Python 3.14.3에서 `python -B -m unittest discover -s tests -v`: 재점검 후 28개 통과. 기존 27개에 파일 읽기 접근 오류 회귀 테스트 1개를 추가했다.
- 실제 로더·SQLite·FAISS를 사용하고 모델 출력은 대역으로 검증했다. 파일별 중복 제거, 본문/이미지만 있는 폴더, 빈 검색어, 분석 실패, GUI 큐 처리, 모델 공유를 포함한다.
- DB 연결 미종료 경고는 남아 있으며 위 2번으로 전달한다. 팀원 원본을 바꿔 경고를 없애지는 않았다.
- 연결 코드의 로더 호출에서 OSError가 발생하면 실패 목록에 넣고 다른 파일을 계속 분석하도록 수정했다. PermissionError를 주입한 회귀 테스트는 수정 전 실패, 수정 후 통과했다. 모델 오류를 숨기지 않는 기존 테스트도 통과했다.
- Python 파일 26개·노트북 코드 셀 31개의 문법 검사와 MD 18개의 로컬 파일 링크 검사를 통과했다. 과거 공부 자료의 코드는 실행하지 않았으며, 현재 코드와 다르다는 표시를 추가했다.
- 숨긴 실제 CustomTkinter 창에서 위젯 생성, 분석·검색 큐, 상태 표시와 결과 카드 생성을 확인했다. 서비스는 대역을 사용했고 실제 모델·파일 열기는 실행하지 않았다.
- 실제 모델 다운로드·검색 품질·GUI 화면을 띄운 시각 검증·앱 재시작 후 검색 복원은 검증하지 않았다.
