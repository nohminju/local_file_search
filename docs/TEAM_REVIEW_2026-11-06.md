PDF 예외 검증은 실제 문제 PDF가 아니라 테스트 대역으로 예외를 주입한 결과다. 별도로 실제 이미지 PDF를 생성해 이미지 추출·인덱싱·파일 결과 연결도 확인했다.

## 내 연결 코드에서 맞춘 부분

- PPTX·PDF 내부 이미지도 `chunk_type='image'`로 오므로 `connection/service.py`에서 원본 파일 확장자로 이미지/문서 이미지 인코더를 선택한다.
- 메타데이터는 기존 파일 경로·페이지 번호를 그대로 사용한다. 본문·이미지 점수를 합치지 않고 파일별 최고 점수 하나와 기본 5개 제한을 유지한다.
- 팀원 알고리즘과 폴더 구조는 바꾸지 않았다.

## 현재 팀원에게 전달할 수정 요청

### DB 연결 종료

- 위치: `database/manager.py`의 `_init_db()`, `save()`, `find_by_id()`.
- `with sqlite3.connect(...)`는 commit/rollback을 처리하지만 연결 자체를 닫지 않는다. Windows 임시 DB 정리에서 파일 사용 중 오류가 발생한 기록이 있고, 현재 테스트에서도 unclosed database ResourceWarning이 남아 있다.
- 요청: `contextlib.closing`과 트랜잭션 context를 함께 사용하거나 `finally: conn.close()`로 함수 종료 시 닫아 주세요.
- 테스트의 gc.collect()는 정리 보조이며 해결책이 아니다. 동일 경로 갱신과 ID·created_at 유지 동작은 테스트를 통과했다.

## 기능 업데이트 시 주의

현재 앱은 FAISS save/load를 호출하지 않으므로 아래 저장 문제는 현재 검색에 영향을 주지 않는다.

- 이전 검증에서 이미지 인덱스 저장 → 본문만 있는 새 매니저를 같은 폴더에 저장 → load 후 이미지 검색 시 IndexError를 재현했다. 이전 images.faiss는 남고 metadata.json의 이미지 정보는 비어 있었다.
- 저장·복원 연결 시 더 이상 없는 인덱스 파일을 정리하고, 불러온 벡터 수와 메타데이터 수가 같은지 검증한다. 본문 인덱스에도 같은 조건을 적용한다.
- add_documents/add_images의 벡터 수·청크 수 검증도 담당자 검토 항목이다. 현재 연결 코드는 같은 순서·개수로 전달한다.
