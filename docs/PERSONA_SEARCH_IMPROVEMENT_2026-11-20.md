# 페르소나 검색 개선·GUI 비교 모드 — 2026-11-20

## 원인과 수정

페르소나 PPTX의 글·표는 읽혔습니다. 실제 슬라이드 XML에도 핵심 표현이 존재하며 그룹 도형 누락은 아니었습니다. 문제는 페이지 단위의 긴 입력을 ko-sroberta에 그대로 넘겨 뒤가 잘렸고, 파일명을 검색 근거로 사용하지 않았다는 점입니다.

| 슬라이드 | 원래 토큰 수 | 모델 전체 입력 제한 |
|---|---:|---:|
| 1 | 324 | 128 |
| 2 | 199 | 128 |
| 3 | 356 | 128 |

`max_seq_length=128`은 모델 캐시의 sentence_bert_config.json 설정입니다. 실제 본문은 특수 토큰 2개를 제외한 126토큰 단위, 32토큰 겹침으로 분할해 원래 파일·페이지 정보와 연결했습니다. 짧은 청크는 그대로 유지합니다.

PDF·PPTX 파일명도 URL 디코딩·한글 NFC 정규화 후 별도 텍스트 청크로 추가했습니다. 개별 파일에 대한 예외 규칙은 없습니다. 파일명·본문·이미지 중 가장 강한 근거 하나로 정렬하며 가산하지 않습니다. 파일명 근거는 GUI·콘솔에 `파일명 유사도`로 표시해 본문 일치로 오인하지 않게 했습니다. 이미지 파일명은 이번에 인덱싱하지 않았으며 이미지 내용 점수는 유지했습니다.

## 실제 샘플 비교

기준은 직전 커밋 09ca810의 ko-sroberta 결과입니다. 새 실행은 동일 38개 파일의 SHA-256 일치와 읽기 실패 0개를 확인했습니다. 모델·하한 0.4/0.2·이미지 인코딩은 유지했습니다. 아래 13개 질의는 기존 비교와 동일하며 추가 페르소나 3개도 포함했습니다.

| 검색어 | 이전 대상 순위 | 수정 후 대상 순위 | 수정 후 1위 근거 |
|---|---:|---:|---|
| 고양이 | 1 | 1 | 이미지 |
| 누워있는 고양이 | 1 | 1 | 이미지 |
| 파란 눈을 가진 고양이 | 1 | 1 | 이미지 |
| 관계형 데이터베이스의 기본키와 외래키 | 1 | 1 | 본문 |
| 동적 계획법의 최적 부분 구조와 중복 부분 문제 | 1 | 1 | 본문 |
| 딥러닝 | 1 | 1 | 파일명 |
| 피자 | 1 | 1 | 이미지 |
| 판다 | 1 | 1 | 이미지 |
| 비행기 | 1 | 1 | 이미지 |
| 기독교와 시인 고정희 | 1 | 1 | 파일명 |
| 바울 사상과 현대 몸에 대한 이해 | 1 | 1 | 파일명 |
| 페르소나와 사용자 경로맵 | 기준 미달·결과 없음 | 1 | 파일명 |
| 인간 컴퓨터 상호작용의 과업 분석 | 1 | 2 | 파일명 |
| 페르소나 경로맵 | 추가 검증 | 1 | 파일명 |
| 사용자 여정 지도 | 추가 검증 | 2 | 본문 |
| 제주 축제 서비스를 이용하는 가상 페르소나 | 추가 검증 | 1 | 본문 |

고양이 3개·데이터베이스·동적계획법은 1위를 유지했습니다. 딥러닝도 1위를 유지했지만 선택 근거는 본문에서 파일명으로 바뀌었습니다. 페르소나 주제 질의는 파일명으로 1위, 제주 축제 이용자 질의는 분할된 본문으로 1위였습니다.

**남은 차이:** 과업 분석 문서는 1위→2위이며 일반적인 인간컴퓨터상호작용 파일명이 근소하게 앞섭니다. 사용자 여정 지도 질의에서는 페르소나가 2위입니다. 이를 유지 또는 완전 해결로 표현하지 않았습니다. 표본 전체의 관련성을 판정한 독립 평가도 아닙니다.

본문 인덱스는 544개 페이지 청크에서 1169개(파일명 24개 포함)로 늘었습니다. 이미지는 573개로 동일합니다. 이번 단일 실행의 분석은 158.5초로 직전 실행 83.2초보다 길었습니다. 실행 조건 차이를 완전히 통제한 속도 실험은 아니지만 긴 본문 전체를 인코딩하는 비용이 늘어난 점은 남습니다.

## GUI에서 직접 비교하는 방법

폴더 선택 → test_esset 선택 → 분석 후 검색창 위의 세 모드를 선택합니다. 변경 후에는 다시 분석해야 새 텍스트 인덱스가 만들어집니다.

| 모드 | 대상과 기준 |
|---|---|
| 통합검색 | 이미지·본문·문서 파일명을 함께 검색. 모델별 하한 필터와 최댓값 정렬·내용 해시 중복 제거 적용. |
| 이미지 검색 | 이미지 내용의 원본 유사도순 상위 5개. 하한 미적용. |
| 본문 검색 | 문서 본문·문서 파일명의 원본 유사도순 상위 5개. 하한 미적용. 파일명 근거는 따로 표시. |

개별 검색은 필터 전 후보와 원본 점수를 비교하기 위한 모드입니다. 통합검색과 결과 수·순서가 다를 수 있고 유사도는 확률이 아닙니다. 작업 중 모드 변경을 막고 선택한 모드를 작업 큐에 전달합니다. 실제 Windows 창에서 세 버튼의 표시와 이미지/본문 모드 전환·설명 변경을 확인했습니다. 실제 모델 검색 순위는 별도 콘솔 평가로 검증했으며 GUI에서 전체 모델 분석까지 다시 수행한 것은 아닙니다.

## 하한이 현재 최선인가

하한만으로 관련성을 판단하는 방식이 최선이라고 볼 수 없습니다. 기존 페르소나 본문 점수는 약 0.386으로 0.4 미만이었지만 무관한 다른 문서가 약 0.49로 앞섰습니다. 단순히 하한을 낮추면 후보는 나타나도 순서는 개선되지 않습니다.

현재는 새 모델을 추가하지 않고 누락된 파일명·잘린 본문을 먼저 보완했습니다. 다음 비교 후보는 파일명/키워드·의미 검색으로 후보를 넓게 수집하고, 질의와 후보를 함께 평가하는 재정렬 모델로 순서를 정한 뒤 최종 표시·거절 기준을 검증하는 방식입니다. Sentence Transformers의 [공식 Retrieve & Re-Rank 문서](https://www.sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)도 후보 검색과 재정렬을 분리합니다. 재정렬 자체는 이번에 구현하거나 성능을 검증하지 않았습니다.

고정 하한은 현재의 기본 필터로 남겨두었습니다. 더 좋은 거절 기준을 정하려면 새 자료의 정답·오답 질의와 모델별 점수 분포를 함께 평가해야 합니다. 현재 수치를 범용 관련성 기준·정확도·확률로 해석하지 않습니다.

## 코드와 기록

- 확장자 선택은 file_loader/document_loader.py의 DocumentScanner.SUPPORTED_EXTENSIONS에 있습니다. database/db_info.py는 메타데이터 자료형입니다.
- connection/text_preparation.py: 모델 토큰 길이 기반 분할과 문서 파일명 청크.
- database/faiss.py: 문서 청크 종류 보존. connection/service.py: 기존 튜플 규격과 파일명 출처를 함께 유지.
- tests/compare_persona_search.py: 실제 샘플 재실행. PERSONA_SEARCH_COMPARISON_2026-11-20.json: 전체 원본 점수와 전후 순위.
- study/는 계속 Git 제외 상태입니다. 샘플과 사용자 문서의 본문은 수정하지 않았습니다.

최종 회귀 테스트는 80개가 통과했습니다(13.213초). 파일명 출처 보존과 이미지 파일명을 본문으로 등록하지 않는 경우도 검증했습니다.
