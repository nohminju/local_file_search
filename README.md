# Local File Search

PDF·PPTX의 본문과 내부 이미지, 일반 이미지 파일을 문장으로 검색하는 로컬 프로그램입니다.

## 설치와 실행

Python과 Tkinter가 필요합니다. 통합 검증에는 Python 3.14 환경을 사용했습니다. 설치와 실행에는 같은 Python 환경을 사용하세요.

```powershell
python -m pip install -r requirements.txt
python app.py --gui
```

콘솔 실행은 `python app.py`입니다. GUI에서는 폴더 선택 → 분석 → 검색어 입력 → 검색 순서로 사용합니다. 첫 실행에는 모델 다운로드가 필요할 수 있습니다.

이 PC에서는 기존 환경을 재사용해 다음과 같이 실행할 수 있습니다.

```powershell
cd C:\Capstone\document-search-demo-v3
& C:\Capstone\document-search-demo-v2\.venv314\Scripts\python.exe app.py --gui
```

## 현재 모델과 연결

실제 샘플 비교 후 본문과 이미지를 다른 모델로 검색하도록 개선했습니다.

| 검색 대상 | 모델 | 벡터 차원 |
|---|---|---:|
| 본문·본문 검색어 | `jhgan/ko-sroberta-multitask` | 768 |
| 이미지·이미지 검색어 | OpenCLIP `xlm-roberta-base-ViT-B-32` / `laion5b_s13b_b90k` | 512 |

이미지와 이미지 검색어만 모델 객체를 공유합니다. `query_encoder/text_encoder.py`는 이미지 검색어용이고 본문 검색어는 `SentenceDocumentEmbedder.encode_query()`를 호출합니다. 본문·이미지는 별도 FAISS 인덱스를 사용합니다. `build_service()` 기본값은 sentence이며 이전 OpenCLIP 본문은 `build_service(document_backend='openclip')`으로 비교할 수 있습니다.

이미지는 배치로 인코딩하고 같은 본문은 한 번만 인코딩한 뒤 원래 파일·페이지 메타데이터에 연결합니다. 본문은 기본 8개씩 배치 처리합니다.

## 검색 결과

- GUI에서 **통합검색 / 이미지 검색 / 본문 검색**을 선택합니다. 통합검색은 모델별 하한을 적용하고, 개별 검색은 비교용으로 원본 점수순 상위 5개를 하한 없이 표시합니다. 본문 검색에는 문서 파일명도 포함하며 근거를 별도로 표시합니다.
- 본문 0.4, 이미지 0.2의 초기 하한을 적용합니다. `DocumentSearch`의 `document_min_score`, `image_min_score`로 조정합니다. **실제 점수의 9개 하한 조합 비교 후 기존 0.4/0.2를 유지했습니다. 범용 최적값이나 관련성 보장은 아닙니다.**
- 각 검색에서 하한을 통과한 점수를 `(원본 유사도 - 해당 하한) / (1 - 해당 하한)`으로 변환하고, **파일별 최댓값 하나**로 정렬합니다. 두 검색에 나와도 합산·가산하지 않습니다. 원본 유사도가 1을 조금 넘는 부동소수점 오차는 정렬 계산에서만 1로 제한합니다.
- GUI·콘솔에는 최댓값을 제공한 본문/이미지/파일명의 원본 유사도를 표시합니다. 같은 정렬값이면 본문을 표시하며, 양쪽 원본 점수는 SearchResult.document_score/image_score에 보관합니다.
- 이 변환은 모델별 하한을 맞춘 운영상 규칙이며 학습된 관련성·확률 보정이 아닙니다. 실제 모델이 무관한 파일에 높은 점수를 주는 오류까지 해결하지는 못합니다.
- 같은 파일의 여러 페이지·그림을 묶고 SHA-256이 같은 내용도 하나만 반환합니다. 동점은 경로 순서로 정합니다.
- 기본 최대 5개이며 하한을 통과한 결과가 부족하면 적게 반환합니다.

이전 본문 모델의 실제 검색 품질·속도 측정은 [11월 17일 기록](docs/SEARCH_AND_UNUSED_CODE_2026-11-17.md)에 있습니다. 현재 모델의 성능 수치로 해석하지 마세요. 본문은 모델 입력 길이에 맞춰 126토큰씩 32토큰 겹침으로 분할합니다. 문서 파일명은 별도 검색 근거로 추가했습니다. 이미지 파일명 검색은 아직 하지 않습니다.

## 지원 범위와 제약

- PDF: 추출 가능한 본문과 가로·세로 모두 100px 이상인 내부 이미지.
- PPTX: 글·표의 본문과 내부 이미지.
- JPG / JPEG / PNG / WEBP: 일반 이미지.
- PPT, HWP/HWPX, DOCX, TXT는 수집하지 않습니다. OCR과 문서 페이지 전체 이미지화는 지원하지 않습니다.
- 파일명은 URL 디코딩 후 NFC로 정규화합니다. 실제 파일 경로는 변경하지 않습니다.
- SQLite는 임시 DB, FAISS는 메모리 인덱스입니다. 재실행 시 다시 분석하며 GUI 재분석은 새 서비스를 만듭니다. 저장·복원 함수는 앱에 연결하지 않았습니다.
- 샘플은 `test_esset` 폴더에 통합했습니다. PPT 파일도 보관하지만 현재 분석 대상에서는 제외합니다. `encode_with_crops()`는 기본 분석에서 사용하지 않습니다.

## 코드와 검증

`app.py`가 객체를 만들고 `connection/service.py`가 분석·검색을 연결합니다. `gui/window.py`가 화면과 작업 큐를 담당합니다. [담당 범위](docs/CODE_OWNERSHIP.md), [통합 변경 정리](docs/INTEGRATION_2026-11-20.md), [활동 기록](docs/ACTIVITY_LOG.md)을 참고하세요.

```powershell
python -B -m unittest discover -s tests -v
```

2026-11-20 회귀 테스트 71개가 통과했습니다. 실제 모델·동일 샘플 비교에서 고양이 관련 3개 질의의 대상 순위는 20/19/19위 → 모두 1위, 데이터베이스는 1위 유지, 동적계획법은 3위→1위, 딥러닝은 5위→1위였습니다. 기본 서비스 경로에서도 실제 샘플 38개를 재분석해 확인했습니다. 추가 질의를 합한 13개 중 기대 대상 1위는 3개→12개였고 페르소나 질의는 미해결입니다. 고정된 로컬 표본의 탐색 결과이며 일반 정확도가 아닙니다. [본문 모델·점수 기준 개선 보고서](docs/TEXT_MODEL_IMPROVEMENT_2026-11-20.md)를 참고하세요.

이전 OpenCLIP 본문 모델의 [실패 기록](docs/REAL_SAMPLE_CHECK_2026-11-20.md)도 보존했습니다. GUI 육안 확인은 하지 않았습니다. Windows FAISS 저장 테스트는 영문 TEMP/TMP 경로를 사용했습니다.
